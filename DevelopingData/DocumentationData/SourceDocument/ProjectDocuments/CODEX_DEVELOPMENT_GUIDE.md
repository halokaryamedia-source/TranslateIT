# Codex Development Guide

1. Always read `MASTER_PROJECT_DOCUMENTATION.md` before editing.
2. Always read the related folder `README.md` before creating or editing files there.
3. Do not create new root folders without approval.
4. Do not place documentation files randomly.
5. Do not place engine files inside documentation folders.
6. Do not place user data inside engine folders.
7. Use clear English names.
8. Update documentation after major changes.
9. Update `LogData` only for important or critical changes.
10. Keep the project structure clean.
11. Follow the existing root structure.
12. Never skip validation before reporting completion.

## Working rule

- Treat the master documentation as the current project contract.
- Prefer small, traceable changes inside the approved folders.
- Keep new implementation details consistent with the documented pipeline and storage rules.
